# Setup Repository Guardrails (Multi-Language)

## Core Objective
Establish a language-agnostic validation layer using the `pre-commit` framework. This ensures that Python code is PEP8 compliant and secure, and C++ code follows project style and static analysis rules before hitting the server.

## Phase 1: Environment Discovery
1. **Identify Languages**: Check for `.py` files (Python) and `.cpp/.hpp/.cc` files (C++).
2. **Identify Build Systems**: Check for `CMakeLists.txt` (CMake) or `pyproject.toml/requirements.txt`.
3. **Tool Check**: Verify if `pre-commit` is installed; if not, prepare to install via `pip` or `brew`.

## Phase 2: Implementation (The `.pre-commit-config.yaml`)

Create a `.pre-commit-config.yaml` in the root. Use the following logic to populate it:

### 1. General Hooks (Always Include)
- `trailing-whitespace`, `end-of-file-fixer`, `check-yaml`, `check-added-large-files`.

### 2. Python Suite (If Python Detected)
- **Formatting**: `psf/black` (The uncompromising formatter).
- **Linting**: `charliermarsh/ruff` (for speed).
- **Type Checking**: `pre-commit/mirrors-mypy`.
- **Security**: `PyCQA/bandit` (to catch hardcoded passwords/unsafe calls).
- **Testing**: pytest

### 3. C++ Suite (If C++ Detected)
- **Formatting**: `mirrors-clang-format`. Ensure it looks for `.clang-format` file.
- **Static Analysis**: `clang-tidy`. 
  *Note: This usually requires a `compile_commands.json` generated by CMake.*
- **Header Guards**: `cheshirekow/cmake-format` (if using CMake).
- **Testing**: gtest or catch2
